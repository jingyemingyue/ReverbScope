# 测量健康

[English](MEASUREMENT_HEALTH.md)

“测量健康”位于分析文本报告的前部和结果概览的顶部。每项问题都包含
稳定代码、严重程度、短标题、解释、证据和下一步操作。它帮助修复测量，
不会给房间评分，也不代表设备或 DAW 已通过验证。

| 状态 | 含义 |
| --- | --- |
| GOOD／正常 | 现有测量检查没有发现问题。 |
| WARNING／警告 | 有需要处理的限制、被拒绝的可选参考或受影响的指标。 |
| INVALID／无效 | 削波、直达声、播放速度或麦克风设备时序诊断表明，本次录音不能支撑可靠的衰减／能量结论。 |
| UNKNOWN／未知 | 某项检查或证据缺失，或无法识别。这不代表通过。 |

总状态的优先级为 **INVALID > WARNING > UNKNOWN > GOOD**。
未提供可选回环是正常情况；已提供但被拒绝的回环会产生警告。仅在未使用的
电气参考中发生时序故障，不会使未补偿的麦克风录音整体失效。
实际测量录音的设备时序故障则会标记为无效，即使直达声置信度为高。

## 证据与操作

| 稳定代码 | 证据与操作 |
| --- | --- |
| `recording.clipping` | 使用现有平顶峰值／削波诊断，包括后来降低音量的导出。降低话放增益或播放电平，移除非线性处理后重新测量。 |
| `direct_sound.medium_confidence` | 使用现有中等置信度和峰前裕量。核对摆位和参考信号。 |
| `direct_sound.low_confidence` | 使用现有低置信度。EDT/T20/T30/C50/C80/D50 和反射时序可能不可靠；改善直达声路径及信噪比后重新测量。 |
| `decay.insufficient_range` | 使用现有 `insufficient_decay_range` 标记、受影响的指标和原因。这不代表 RT60 = 0；降低噪声、改善摆位，在电平余量内调整播放电平。 |
| `playback.sample_rate_mismatch` | 使用现有播放速度诊断。检查工程采样率、导入转换、接口采样率和播放转换。 |
| `playback.time_stretch` | 使用现有时间拉伸诊断。关闭 Warp、Flex、Follow Tempo（跟随速度）、音乐模式和片段拉伸。 |
| `device.timing` | 使用现有缓冲欠载／溢出、设备报告的采样率或时序故障诊断。增大缓冲区／延迟，检查采样率和时钟，关闭其他音频程序后重新测量。 |
| `noise.limited_range` | 使用现有衰减范围不足标记和有限的峰值与噪声之差。噪声、时长或摆位可能限制可用范围；改善录制条件。 |
| `reflection.truncated_window` | 使用现有窗口截断标记和请求／实际可用窗口。延长尾音录制时间，增加扫频间隔，保留完整响应。 |
| `loopback.rejected` | 使用现有电气参考被拒绝的信息。检查路由、电平和时钟；修正参考，或明确使用未补偿测量。 |
| `analysis.warning` | 无法识别的分析器警告会保留原有证据并继续显示。 |

其他代码解释录制尾音太短、指标不可靠或未计算、频带未被激励或范围未知，
以及缺失削波、噪声、置信度或结果证据。无法识别的播放速度诊断使用
`playback.unknown_diagnosis`，不会被凭空解释为时间拉伸。

## 工程边界

`reverbscope.measurement_health.derive_measurement_health(result)` 返回使用
当前界面语言的不可变临时视图。它只读取现有 `AnalysisResult`，不运行 DSP，
不修改指标有效性。问题代码和严重程度不受语言影响。
CLI 符号和 GUI 颜色均配有文字：未知证据为中性色，警告为黄色，无效测量为红色。

没有 0–100 分数，也没有新增数值合格阈值。范围诊断采用核心已有的有效性判断：
`core.decay._fit_metric` 要求可用范围覆盖评价范围及配置的噪声裕量，
且衰减曲线包含足够采样点。测量健康不会重新拟合或重复作出 DSP 判断。
它不会根据未校准的 dBFS 电平推断声学噪声是否合格；缺失噪声或峰值与噪声之差
的数据仍为未知，不能当作零。

版本 1 schema 的设备诊断以英文句子保存，因此本模块集中识别现有诊断生成器
的句式，再进行翻译。“没有溢出”等偶然出现的关键词不会被诊断为设备故障。
无法识别的警告会保留证据并保持警告状态。

CLI 的 `--format json`／`--json` 输出，以及 result/session/project schema
均保持不变。不持久化任何测量健康字段。Python 调用者可明确调用派生函数；
本批没有新增机器可读的 CLI 输出，也没有新增运行时依赖。
合成数据和离屏界面测试不代表真实硬件或 DAW 验证通过。
