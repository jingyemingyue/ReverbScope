## §0 一页摘要

**现状。** `main` 上是页面式的表单界面（首页 → 模式页 → 结果页，外加对比页和项目页）。另有四条 GUI 改版草稿并行推进，都没有合并：

- #55：Claude 做的“测量工作台”；
- #56 → #57 → #58：Claude、Grok、Cursor、Codex 先后叠加的“工作站”。#58 的改动是 232 个文件、+32,397/−6,714 行。

**判断。** “人机感满满的拼凑品”，根源不在“样式不够好看”，而在下面四件事：

1. **没有统一的产品和交互规格。** 每个会话都自己发明一套信息架构。同一组数字在同一屏出现三次；功能按审计顺序一张一张往页面上追加。
2. **信息没有层级。** 结论、证据、原始数据和操作说明的视觉权重完全一样。整页都是卡片和说明文字。
3. **视觉系统只做到了“QSS 换肤”。** 有颜色 token，却没有字号阶梯、间距体系、图标和组件语义。同一个 `FindingCard` 同时扮演四种角色。
4. **文案是审计报告和命令行的口吻。** 界面里出现命令行参数、文件名、文档章节号、临时目录的完整路径，甚至有自相矛盾的句子。

**目标。** 只做一个“测量项目窗口”：

- 左边是测量列表（项目 › 位置 › 测量）；
- 中间是**结论优先**的结果区，层次依次是：结论 → 4 个关键数字 → 可交互图表 → 表格 → 原始报告；
- 测量本身用分步向导面板完成。

整体要克制、有层级、一致、中文优先。窗口安静地回答录音人的三个问题：*这里能录吗？这个位置有什么问题？换位置之后变好了吗？*

**做法。** 按以下顺序推进，每个阶段一个 PR：

1. 先定决策和基线；
2. 再建设计系统和组件库；
3. 然后依次重做外壳、结果、测量流程、对比与项目、首页与设置；
4. 最后上真机验收。

每个 PR 都附前后对比截图，并且要通过 §16 的完成定义和“人机感”评审表。

**不变。** 以下几条保持不变：

- 每个数字都带有效性标记；
- 电平只用 dBFS；
- 不打总分；
- 完全离线；
- 只用 LGPL 的 Qt 模块；
- 命令行和 GUI 的数字、用词一致；
- 中英双语；
- 安全规则（停止键和 Esc、每次测量前确认电平）；
- 合成数据每屏都有标记。

## §1 项目整体框架汇总

### 1.1 定位

ReverbScope 是一个开源（Apache-2.0）、不依赖任何 DAW 的**录音环境分析器**。它用指数正弦扫频（ESS）做反卷积，得到脉冲响应，再从中算出混响时间（EDT、T20、T30，以及 RT60 估计）、频率响应、本底噪声、早期反射、低频共振、清晰度（C50、C80、D50、中心时间）和摆位几何。分析结果之上有两层：一层按“录音配置”给出解读（人声、配音、木吉他、鼓、房间话筒、合唱、通用），另一层是“测量健康”，检查这次测量本身是否可信。

它要回答三个问题：

1. **这个房间能不能录？**
2. **这个位置有什么问题？**
3. **移动话筒或演奏者之后有没有改善？**（两次测量对比，以及多位置项目）

### 1.2 受众（ARCHITECTURE_V1 §1）

| 受众 | 要给他们什么 | 他们永远不应该需要 |
| --- | --- | --- |
| 录音师、学生、家庭录音者（**GUI 的主要用户**） | 签名的桌面应用、DAW 四步流程、独立模式、中英文用户指南、两个位置的对比 | Python、终端、账号、联网、校准话筒 |
| 集成者和研究者 | `pip install`、公开 API、带 JSON Schema 的结果文件、CSV 导出、`analyze-ir` | 逆向 JSON、导入私有模块 |
| 贡献者 | 不碰 DSP 也能加录音配置和翻译、跨平台 CI、ADR | DSP 背景 |
| 译者和教师 | gettext 词条 | 改 Python |

### 1.3 不可违背的产品原则

这些原则继承自需求书和 ARCHITECTURE_V1 §2、§3.3，GUI 重构不能碰：

- **不依赖 DAW**：WAV 进，WAV 出，不用任何 DAW SDK，不做插件。
- **核心优先**：`reverbscope.core` 是纯 NumPy/SciPy，GUI 只是薄前端。
- **科学正确**：用公开发表的方法，每个指标都带有效性标记，宁可不给数，也不猜一个数。
- **数字诚实**：电平用 dBFS（未校准），不给 dB SPL，**不给房间总分**。
- **离线**：不联网、不收集遥测、不检查更新，CI 会检查 `src/` 下有没有网络导入。
- **法律清晰**：不收录第三方代码，依赖都做过许可证审计；只用 PySide6 Essentials（LGPL），禁止 GPL 的 Qt 模块。
- **安全**：电平保守，每次测量都要确认电平；停止要立刻静音；不改系统音频设置。
- **1.0 不做的事**：插件、时钟漂移校正、dB SPL、多位置几何、**3D 房间模型**、吸声计算、自动 EQ、云和账号。

### 1.4 代码分层（main 现状）

```
src/reverbscope/
  core/            纯 DSP：sweep、deconvolution、decay、noise、reflections、resonance、
                   placement、loopback、linearity、playback_speed、compare、averaging、
                   pipeline（analyze / analyze_impulse_response）
  models/          数据类：AnalysisResult、MeasurementSession、configuration、comparison；
                   result_load / loadutil 负责读回
  interpretation/  profiles（7 个录音配置）、verdicts（对比判定）、overview（项目总览）、explain
  health.py        测量健康 assess()
  labels.py        有效性、严重度、主题的显示用词
  io/              wav、session_store、project_store、recent、exporters（csv）、jsonutil
  audio/           后端接口、portaudio、fake（伪后端）、inventory、playrec
  cli/             main（2940 行）、render（2454 行）、console、interactive、config、report
  ui/              PySide6 前端（main：16 个模块，6,375 行）
  i18n.py, locale/ gettext；zh_CN
  settings.py, edition.py, diagnostics.py, demo.py, logging_config.py
```

#58 在此基础上新增了 `display/`（curves、etc、timefreq：显示用的变换）、`geometry/`（room、paths、scan：房间几何和扫描导入）、`ui/views/`、`ui/room/`，以及 `plotkit.py`、`navigator.py`、`inspector.py`、`measure_strip.py`、`workspace.py` 等，`ui/` 合计 14,937 行。

**依赖方向**是 `ui → (interpretation, health, labels, io, audio, models) → core`。`ui` 不得被任何非 ui 模块导入；`ui` 和 `display` 不做任何分析计算。

### 1.5 数据流

```
测试信号（sweep.wav + .reverbscope-sweep.json）
   │
   ├─ 通用 DAW 模式：用户在 DAW 里播放并录音 → 导入录音文件
   └─ 独立模式：audio 后端播放和录音（fake 后端用于演示和测试）
   ▼
core.pipeline.analyze(recording, reference, settings) → AnalysisResult（每个指标都有 Validity）
   ├─ interpretation.interpret(result, profile) → findings（解读，加载时重新推导，不存盘）
   ├─ health.assess(result)                     → 测量健康（good/warning/invalid/unknown）
   └─ compare / verdicts / overview             → 对比判定、项目总览
   ▼
呈现：cli/render（终端）  |  ui（桌面）    ← 两者必须同数同词
   ▼
io.session_store.save_measurement → 会话文件夹；io.project_store → project.json
```

### 1.6 存储

- **会话文件夹**：`session.json`、`result.json`、`impulse_response.wav`、`recording.wav`（按设置复制）、`sweep.reverbscope-sweep.json`。路径在文件夹内写成相对路径，整个文件夹可以移动。
- **项目文件夹**：`project.json`（房间名、备注，以及 `positions[]: {label, session_dirs[]}`），每次测量各占一个普通会话文件夹。
- **`REVERBSCOPE_HOME`**（默认 `~/.reverbscope`）：`settings.json`、`recent_sessions.json`、`reverbscope.log`；#58 又加了 `ui.ini`（界面布局状态）。

### 1.7 发行形态（EDITIONS）

- **桌面版**含 Qt、PySide6 和 matplotlib（#58 加了 pyqtgraph）；**终端版**不含任何 GUI 依赖。
- **开发者工具**（开发者菜单、独立模式里的高级音频选项）在源码安装时默认开启，打包安装时默认关闭，可以在设置里打开。

### 1.8 质量门（CI 九个作业）

- 代码风格和类型检查：`ruff`、`ruff format`、严格 `mypy`（其中一次在没有 PySide6 存根的环境里跑）。
- 文档检查：文档链接、CLI 文档、文档站构建。
- 安全检查：`check_src_safety.py`（不许网络导入和 shell 调用）、action 版本固定。
- JSON Schema 检查。
- 三个平台的完整测试套件，离屏运行，core 和 models 的分支覆盖率要求 85%。
- sdist 和 wheel 构建；许可证包和 GPL 模块门。

GUI 测试用 `QT_QPA_PLATFORM=offscreen` 运行。**中文门**由 `tests/zh_tokens.py` 的 `ALLOWED` 白名单决定：中文界面只允许出现白名单里的拉丁词，`Ctrl` 这个词会被拒绝。README 里的截图由 `scripts/render_readme_assets.py` 生成。

- `release/0.5.0`：候选版线，只收修复。

## §2 现状诊断：为什么像“拼凑品”

### 2.1 方法与边界

在本机用 `QT_QPA_PLATFORM=offscreen` 渲染了 `main`（0.5.0b3）的全部页面：首页、DAW 模式、独立模式、演示、结果页的 8 个标签、对比、项目、设置、配置说明、最小窗口。用的是合成演示数据（`reverbscope demo` 加一个含 A、B 两个位置的项目），分中文浅色、中文深色、英文浅色三组。#58 的情况来自它在 `docs/images/gui2/` 和 `docs/images/gui2/acceptance/` 里自带的截图，以及它的代码和设计文档。

离屏截图看不到原生窗口边框、Retina 效果和系统菜单栏。凡是涉及这些的结论，都标了“需真机核对”。

“人机感”在本文里的定义是：**界面像是程序按数据结构自动堆出来的，而不是为人设计的**。具体表现是表单直出、说明书一样的大段文字、所有东西一样重要、术语和路径裸露在外、同样的内容反复出现。

### 2.3 #55–#58 工作站路线的评估

**做对了、要保留的：**

- pyqtgraph 交互图表（`ui/plotkit.py`、`ui/views/*`）：缩放、平移、双击适配、悬停读数（带单位）、叠加、差值图、导出。频率图里**扫频范围以外的部分加了阴影**，这是诚实的做法。
- `display/` 层：把显示用的平滑、ETC、时频变换和 core 分开，并且有测试。
- 左栏测量列表：“选中、叠加勾选、基准”三种状态互不替代。
- `WorkspaceModel`（工作区模型）、`ProjectLoader`（后台线程加载）、`ui.ini` 布局保存、显示缓存的内存预算。
- 扩大了未保存测量的保护范围；切换视图时不会停止正在进行的测量。
- `GUI_REFERENCE_AUDIT.md` 的规矩：只借鉴想法，不复制其他软件的代码、图标和色表。

**没解决、甚至更糟的：**

- **同屏信息过载。** 菜单、10 个视图标签加 2 个右侧标签、左栏、右侧检查器、底部 10 个控件的测量条、状态栏全部同时在屏。960×640 时测量条折成两行，图表只剩大约三分之一的高度（见 `acceptance/zh_CN_960x640_dark_fr.png`）。
- **同一组数字在一屏里出现三次**：总览指标卡、测量健康卡、右侧检查器的“关键数值”。
- **总览页还是 main 的卡片堆**，只是挤进了中栏，问题 12–17 原样保留。
- **常驻测量条**把设备配置变成了永久的视觉噪音；“就绪”做成了一个按钮。
- 左栏和检查器都显示临时目录的完整路径。
- **3D 房间视图**（用户输入房间尺寸和坐标、图像源、PLY 扫描导入）和 ARCHITECTURE_V1 §3.3“3D room models 不在 1.0 范围内”冲突，而且被当成主视图之一。
- **产品界面去掉了演示**（#55、#58），和 ARCHITECTURE_V1 §5.8 冲突，也失去了“不需要硬件就能先体验”的首次使用路径。
- 控件风格混杂：GroupBox 标题里带复选框、SpinBox 一个叠一个、参数和说明文字常驻在图表上方。
- **四条线由不同代理各自推进**，各带一套设计文档，没有共同规格；改动 3 万多行，涉及 82 个测试文件；全部仍是草稿，原生 Mac 验收一项都没跑（见 `MAC_GUI_ACCEPTANCE.zh-CN.md`）。

### 2.4 根因归纳

| 编号 | 根因 | 表现 | 本准则对应章节 |
| --- | --- | --- | --- |

## §4 北极星与设计原则

### 4.1 北极星

> 打开 ReverbScope，**30 秒内**知道：这个位置能不能录人声、主要问题是什么、下一步该做什么。需要证据时，**点一下**就能看到可以缩放和读数的曲线。整个窗口安静、有序，像一件打磨过的录音棚工具，而不是一份审计报告。

### 4.2 三个典型用户和他们的首要路径

| 用户 | 背景 | 首要路径 | 成功的标志 |
| --- | --- | --- | --- |
| 家庭录音者 | 有 DAW 和一支话筒，没有声学背景 | 欢迎页 → 用 DAW 测量 → 4 步向导 → 结论页 | 不看用户指南也能完成；能复述“问题是什么、怎么改” |
| 录音工程师 | 有音频接口，想比较两个话筒位置 | 打开项目 → 测量新位置（接口向导）→ 对比 | 3 分钟内得到“B 比 A 好在哪里”，且知道哪些结论不可比较 |
| 学生或教师 | 学习 RT60、清晰度 | 打开示例项目 → 结论 → 衰减图和频率图 | 能把数字、曲线和概念对上 |

### 4.3 设计原则

| 编号 | 原则 | 要 | 不要 |
| --- | --- | --- | --- |
| P1 | 一屏回答一个问题 | 每个视图顶部能用一句话说明它回答什么 | 一页里同时放结论、原始表格、配置表单和说明书 |
| P2 | 结论在前，证据在后（渐进披露） | 按 4 层展开：结论 → 关键数字 → 图表 → 表格和原始报告 | 默认展开所有频带、所有检查、所有备注 |
| P3 | 可信度是一等视觉通道 | 有效性在任何地方都用同样的标记；无效的数不以正常数字样式显示 | 把“范围不足”的数字和有效数字画得一样 |
| P4 | 用状态代替说明 | 向导显示步骤状态；按钮禁用时说明原因；实时检查（采样率不一致、电平过高） | 9 行说明书；点了才弹框告诉你缺什么 |
| P5 | 克制 | 留白、对齐、少量强调色 | 仪表盘、评分环、渐变、玻璃效果、没有意义的动画、营销口号 |
| P6 | 一个含义一个组件，一个组件一个含义 | 解读、健康检查、判定、位置各用各的组件 | 一张卡片什么都装 |
| P7 | 中文优先的排版 | 不全大写；用中文标点；数字和单位之间加空格；短句 | 直接把英文的排版习惯照搬到中文 |
| P8 | 操作就近 | 动作放在它作用的对象旁边（图表的导出放在图表工具条上） | 所有按钮堆在页面顶部或底部 |
| P9 | 安全显性 | 发声时停止按钮始终可见，Esc 永远有效 | 停止按钮要滚动才能找到 |
| P10 | 尊重平台 | 快捷键、对话框、菜单、“在 Finder 中显示”遵循各平台习惯 | 在 macOS 上显示“文件(F)” |

### 4.4 反目标（明确不做）

- 房间总分、星级、红黄绿灯式的整体评价、仪表盘式的圆环或刻度表。
- AI 聊天助手、自然语言问答（实验分支 `experimental/guided-acoustic-assistant` 不在本准则范围内，也不得混进 GUI 重构）。
- 装饰性插画、启动动画、品牌渐变。
- 为“看起来专业”而堆参数：参数只在需要时出现。
- 3D 房间模型（D5）。

### 4.5 参考对象（只学原则，不复制资产）

- **Apple HIG**：侧边栏、sheet、检查器的层级关系，以及克制的配色。
- **Logic Pro、Studio One**：浏览器和检查器按需出现；顶部的控制区很紧凑。
- **REW**：测量列表加叠加曲线的工作方式（#58 已经借鉴）。
- **Smaart**：把“数据可信度”可视化的思路。
- **Sonarworks SoundID Reference**：测量向导分步进行，每一步都有实时检查。
- **iZotope RX**：深色专业图表的克制。

使用规则同 `GUI_REFERENCE_AUDIT.md`：只借鉴交互惯例，并逐条登记。

## §5 硬约束（违反即不合并）

| 编号 | 约束 |
| --- | --- |
| C1 | **数值来源。** 界面上显示的每个测量数字都必须来自 core、models、health、interpretation。`ui` 和 `display` 只做显示变换（平滑、抽样、坐标映射）；凡是做了显示变换的地方，图上必须标注（比如“显示平滑：1/6 倍频程”）。 |
| C2 | 每个数字都有单位和有效性；无效值不能用正常样式显示；“仅供参考”的样式必须有图例说明。 |
| C3 | 不评分，不给综合分；判定只按方面给出（混响、清晰度、早期反射、本底噪声、低频）。 |
| C4 | 电平一律用 dBFS（未校准），界面上不出现 dB SPL 数值。 |
| C5 | 离线：`src/` 下不许有网络导入。外部链接（比如用户指南）只能用 `QDesktopServices` 交给系统浏览器打开，并且由用户点击触发。 |
| C6 | Qt 只用 PySide6 Essentials（QtCore、QtGui、QtWidgets、QtSvg 等）；禁止 QtCharts、QtGraphs、QtDataVisualization、QtWebEngine 等 Addons 或 GPL 模块。CI 的 GPL 模块门必须通过。 |
| C7 | 新依赖、图标、字体、色表都必须做许可证审计，并写进 `docs/DEPENDENCIES.md`、许可证包脚本和 `GUI_REFERENCE_AUDIT.md`。 |
| C8 | 安全：电平确认每次测量都要问，不保存；停止和 Esc 必须立即静音；切换视图不停止测量，但测量期间停止按钮必须始终可见；测量期间禁止修改设备设置。 |
| C9 | 合成数据在每一屏都有标记；截图、替代文本和图表导出都要标“合成演示数据”。 |

| C14 | Git：只进 `main` 那条线；不强推；不删远端分支；不发布 Release，不打 tag；不改许可证。以上几条维护者明确同意的除外。 |

```
└────────────────────────────────────────────────────────────────────────────────┘
```

- **侧栏**：项目 › 位置 › 测量，三层树。每个测量有：状态点（测量质量）、叠加勾选框（☑）、基准星标（★）、颜色条（叠加时的曲线颜色）。底部是“测量新位置”。没有项目时显示“最近”列表。可以折叠成 56 px 宽的图标栏。
- **上下文栏**：面包屑，加当前对象的主操作（最多 1 个强调色按钮，比如“保存”），其余操作收进“⋯”菜单。
- **视图切换**：一级视图**不超过 8 个**，用分段标签（不再有右侧的第二组标签）。“频谱（时频、瀑布）”是“频率”和“时间”视图里的二级切换，“摆位”并进“反射”视图。
- **详情抽屉**：原检查器里只该“按需查看”的内容放在这里：测量条件、文件路径、有效性明细。**不重复**结论页上已有的数字。
- **任务条**：只在有后台任务时出现。测量时它是唯一一个、始终可见的停止入口（C8）。
- **状态栏**：删除，它的功能由任务条和 toast 接管。

```
└──────────────────────────────────────────────────────────────────┘
```

**DAW 路径的四步：**

1. **测试信号**
   - 采样率用分段选择（44.1 / 48 / 88.2 / 96 kHz，“更多 ▾”里是 `SUPPORTED_SAMPLE_RATES` 的其余值）。
   - 时长用预设：短 5 s / 标准 10 s / 长 20 s / 自定义。
   - 峰值电平默认 −12 dBFS，旁边一句说明。
   - 点“导出测试信号…”。导出后显示文件卡：文件名、“在 Finder 中显示”，以及一句“附带的 .json 要和 WAV 放在一起”。
   - 选“我已有测试信号”可以直接指定参考文件。
   - 完成条件：已导出，或已指定参考。
2. **在 DAW 录音**
   - 先选 DAW：Pro Tools / Logic Pro / Cubase / Studio One / Ableton Live / REAPER / FL Studio / Bitwig Studio / 其他。
   - 选完后显示这款 DAW 的 4–6 条检查项。内容取自 `docs/user-guide/daw-setup*.md`，是可以勾选的清单，勾选状态不保存，也不是必填。
   - 共同的重点项要突出：关掉时间伸缩、旁通插件、先用低音量、导出时不要标准化、不要裁切。
   - 末尾是“完整的 DAW 指南”链接。
   - 原来那 9 行说明全部删除。
3. **导入录音**
   - 拖入或选择文件。
   - 显示文件卡（时长、采样率、声道数）。
   - 声道选择用单选列表，每个声道带峰值条，默认选自动结果。**每个声道的峰值由 core 或 io 里的纯函数计算**；如果现在没有这样的函数，先单独提一个 PR 加上并写测试（D11），GUI 里不写 DSP。
   - 采样率不一致、文件太短、读取失败都在步骤内用一行提示说明，不弹框。
4. **测量信息**（和接口路径共用这一步）
   - 项目和位置：从项目进入时自动填好。
   - 房间名、话筒。
   - **录音配置用卡片选择**：7 个配置，每张卡有图标、名称和一句话说明，点“它关注什么”打开侧边说明（`profile_dialog` 的内容）。
   - **卷尺测量**默认折叠，标题是“添加卷尺测量，可以得到扬声器高度等几何信息”；展开后用 2D 侧视示意图（§10.3），不再用 3D。
   - 主按钮“分析”。不能点时，下方用一行字写明原因（比如“先导入录音”）。

**分析中**：向导内显示进度面板，写清当前阶段（“正在定位扫频…”）。core 没有进度回调时，只显示不确定进度和一句“通常只需几秒”；**不做假的百分比**。如果要加进度回调，单独开 PR 并写 ADR。

**完成后**：向导关闭，跳到新测量的“结论”视图。侧栏里新增一条，标“未保存”。

### 7.3 新测量向导：音频接口路径（3 步）

1. **设备与声道**
   - 输入设备和输出设备，推荐的组合标 ★。
   - 采样率用分段选择。
   - **声道连线图**：
     ```
     输出  声道 [1 ▾]  ──▶  扬声器
     输入  声道 [1 ▾]  ◀──  话筒
     回采  [未使用 ▾]
     ```
   - 设备的实际采样率和所选不一致时，用一行提示说明。
   - 主机 API（WASAPI、ASIO 等）放在“高级”折叠区里；开发者版的延迟、独占模式、Core Audio 设置采样率也放在同一个折叠区。
   - “刷新设备”是一个图标按钮，放在设备下拉框旁边。
2. **电平与安全**
   - 播放电平用滑块（−40 到 0 dBFS），刻度上标出安全区（`SAFE_MAX_LEVEL_DBFS`），默认值是 `DEFAULT_STANDALONE_LEVEL_DBFS`。
   - 超出安全区时，必须勾选“我已把监听音量调低”。**每次测量都要勾，不保存**（C8）。
   - 安全提示只写一句，不用整条橙色横幅。
   - 扫频时长用预设。
3. **测量信息**：和 DAW 路径的第 4 步共用。

**开始测量**：

- 大号主按钮“开始测量 ⌘↩”。
- 测量中，任务条和向导里的测量面板同时显示：阶段（正在播放扫频 / 正在录制尾音 / 正在分析）、已用时间和剩余时间、大号的“停止（Esc）”。
- 允许切换视图，任务条一直在。
- **两个时钟的警告**改成步骤内的阻断提示，主按钮是“取消”，次按钮是“仍然测量”。保持现有“按按钮角色判断”的语义（`ask_separate_clocks`）。

**规则：**

- **测量质量**（原“测量健康”，改名见 §11.3）收成一行：总体状态、主要问题、通过数。点“详情 ▾”展开检查列表：有问题的检查默认展开，并显示原因、影响和做法；通过的检查只列名字。“直达声置信度”移到这里，不再占一个指标卡。
- **4 个指标卡**结构固定：名称、数值加单位（大号等宽数字）、一行背景说明、可选的迷你图或状态。

  - 点击指标卡跳到对应视图。
  - 4 个指标依次是：RT60、C50、本底噪声、最强早期反射。

### 8.1 Token 的三层结构

1. **原始色板**：灰阶、强调色的色阶、各状态色的色阶。

### 8.5 间距与布局

- **间距 token**（4 pt 网格）：`space.1 = 4`、`2 = 8`、`3 = 12`、`4 = 16`、`5 = 20`、`6 = 24`、`8 = 32`、`10 = 40`、`12 = 48`。
- **页边距**：24；内容宽度 ≥ 1280 时为 32。区块间距 24，卡片内边距 16，卡片之间 12。
- **控件高度**：macOS 28，Windows 和 Linux 32。按钮的水平内边距 12。
- **控件宽度跟内容走**：采样率 160，数字输入 120，短文本 280，路径和长文本才拉伸。**禁止把短输入拉满整行**（问题 7）。
- **表单**：标签列 120–160 并右对齐（中文可以左对齐，但全局必须统一）；每行最多一个控件加一个辅助按钮。
- **阅读型视图**（结论、项目总览、报告）的内容最大宽度 1120，居中；**图表视图**占满宽度。
- **断点**：
  - ≥ 1440：侧栏 + 内容 + 可以推开内容的抽屉；
  - 1024–1439：抽屉以覆盖方式出现；
  - < 1024（最小 960×640）：侧栏自动折叠成图标栏。

### 8.6 形状与层次

- **圆角**：徽章和小控件 4，按钮和输入框 6，卡片 10，sheet 和弹层 14。
- **阴影**：只在 sheet、弹层、toast 上用一个阴影 token；卡片只用 1 px `border.subtle`，不加阴影。
- **禁止**：卡片里套卡片（问题 9），GroupBox 套 GroupBox。分组用标题加间距，或者一条分隔线。

### 8.7 图标

- 用 Lucide 子集（D7），尺寸 16、20、24，线宽 1.75，颜色取文字 token；用 `QSvgRenderer` 渲染到当前 DPR 的 pixmap，每个颜色缓存一份。
- **建议的映射**（Phase 1 固化）：
  - 用 DAW → `file-audio`；音频接口 → `audio-lines`；示例项目 → `folder-open`；
  - 话筒 → `mic`；扬声器 → `speaker`；保存 → `save`；导出 → `download`；复制 → `copy`；设置 → `settings`；
  - 对比 → `git-compare`；报告 → `file-text`；频率 → `chart-line`；衰减 → `trending-down`；反射 → `radio`；噪声 → `waves`；
  - 停止 → `square`；开始 → `play`；基准 → `star`；在 Finder 中显示 → `folder-search`。
- 应用图标保留现在 `widgets.app_icon()` 的自绘版本，Phase 7 再评估是否做 `.icns`/`.ico` 精修。

### 8.8 动效

- 时长 120、180、240 ms，缓动用 OutCubic。只用在：抽屉开合、折叠展开、sheet 进出、toast 进出。
- 数字不做滚动动画。
- 设置里提供“减少动态效果”开关；开了以后所有时长归零。

### 8.9 密度

- 应用整体用一种舒适密度。
- 表格紧凑：行高 28（macOS）或 30，数字右对齐，表头用 `type.body-strong` 和 `text.secondary`，不显示行号，交替行底色很淡，不画网格线（只画行分隔线）。

## §10 图表规范

### 10.1 技术

- 用 pyqtgraph 0.14.0（D3）。#58 的 `plotkit.py` 作为底座，外面统一包一层 `ChartPanel`。
- 图表的样式全部来自 token；字体和界面一致（D9）；开启抗锯齿。
- 数据点超过 1 万时做峰值保持抽样（显示变换，不改数据）。
- 关掉 pyqtgraph 默认的 ViewBox 右键菜单和自动范围按钮，换成我们自己的菜单：适配、导出 PNG、导出 CSV、复制当前读数。

### 10.2 公共交互

| 操作 | 行为 |
| --- | --- |
| 滚轮 | 以光标为中心缩放横轴；按住 ⇧ 缩放纵轴 |
| 拖动 | 平移 |
| 双击 / 点“适配” | 恢复默认范围 |
| 悬停 | 读数栏显示：横坐标、纵坐标、曲线名（不弹浮动提示框） |
| 点图例胶囊 | 显示或隐藏这条曲线 |

坐标轴：

### 10.3 各图表规格

### 10.4 用色规则

- 测量曲线按侧栏颜色分配，颜色跟着测量走，切换视图时不变。
- 频带用顺序色阶。
- 网格用 `border.subtle`，坐标轴文字用 `text.secondary`。
- 深色模式用同一套 token 的深色值。

### 10.5 导出

- **PNG**：2 倍分辨率，带页眉（测量名、日期、录音配置），合成数据要盖“合成演示数据”章（C9）。
- **CSV**：调用现有的 `io/exporters`，和 `reverbscope export` 的数字完全相同（C11）。

### 10.6 无障碍

- 每个图表都有一句可访问描述（`setAccessibleDescription`），比如“频率响应，B-1，在 110 Hz 有 +11 dB 的峰”。
- 每个图表都能一键跳到对应的数据表。

- GUI 和 CLI 措辞不同时，用 pgettext 上下文区分。
- 每个 PR 都附中文和英文截图，检查截断和错位（§16）。

## §12 交互规范

### 12.1 反馈的层级（从轻到重）

| 层级 | 用于 | 组件 |
| --- | --- | --- |
| 行内 | 字段错误、按钮禁用的原因、步骤内的检查结果 | `FormRow` 的错误、`Callout`（小） |
| 页内提示 | 和整页相关的情况（合成数据、两个时钟、只有一对位置） | `Callout` |
| Toast | 不打断的成功提示（“已保存到 B-1 · 在 Finder 中显示”） | `Toast` |
| 模态 | **只用于**：危险或不可撤销的操作（替换、丢弃未保存测量）、系统文件对话框、程序缺陷报告 | `ConfirmDialog`、系统对话框 |

现在 `ui/` 下 36 处 `QMessageBox` 调用，在 Phase 2–6 里逐个按上表归类改掉。附录 C 列出主要的几处。

### 12.2 禁用要说明原因

主按钮不能点时：悬停提示和按钮下方的一行字同时说明原因（“先导入录音”“先勾选‘我已把监听音量调低’”）。不允许出现“能点，点了才弹框说不行”的情况（问题 10）。

### 12.3 长任务

- 测量：确定进度（现有的 `MeasureWorker.progress`），加阶段文字。
- 分析：不确定进度，加阶段文字。没有 core 回调时，不做假进度（D11）。
- 加载项目：用后台线程（#58 的 `ProjectLoader`），列表逐条出现。
- 关窗口或退出时，等后台线程结束（沿用现在的 `shutdown_workers`，C12）。

### 12.4 未保存的测量

- 侧栏里标“未保存”加一个圆点，上下文栏的“保存”用强调色。
- 新建、打开、关闭、从列表移除之前，弹出“保存… / 不保存 / 取消”。语义和测试保持不变（C12）。

### 12.5 选择模型（沿用 #58 的三种状态，互不替代）

- 单击：设为当前测量（视图显示它）。
- 勾选框：叠加到图表上。
- 星标：设为基准（全局只有一个）。

### 12.6 拖放

| 拖入 | 行为 |
| --- | --- |
| WAV、AIFF、CAF、FLAC 等录音 | 打开 DAW 向导的第 ③ 步，并预填这个文件 |
| 会话文件夹或 `session.json` | 打开这次测量 |
| 项目文件夹 | 打开项目 |
| 脉冲响应 WAV（在“我已有脉冲响应”路径中） | 导入 |

### 12.7 键盘

- Tab 顺序和视觉顺序一致；焦点环用 2 px `focus.ring`（现在的 QSS 没给按钮画焦点环，要补上）。
- 所有快捷键都在菜单里显示。
- 向导里 ⌘↩ 是“下一步”或主操作；Esc 的规则见 §6.5。

### 12.8 界面状态的保存

- 保存的内容：窗口几何、侧栏和抽屉开合、上次停留的视图、各视图的图表范围、折叠区状态。
- 保存在 `REVERBSCOPE_HOME/ui.ini`（C13）。
- “视图 ▸ 恢复默认布局”可以一键复原。
- 读不了的状态直接丢弃，回到默认值，不报错。

### 12.9 错误信息

一句人话说明发生了什么，加一句做法，加“复制详细信息”（日志路径和错误文本）。程序缺陷沿用 `_gui_excepthook`：一个对话框，回溯写进日志。

## §13 平台、无障碍与性能

### 13.1 macOS

- 用系统菜单栏；“关于”“设置”“退出”通过 `QAction` 的 MenuRole 放进应用菜单。
- 用 ⌘ 快捷键；用“在 Finder 中显示”。
- 中文菜单不显示“(F)”这类助记符：要**在真机上核对**，必要时只在非 macOS 平台的菜单文字里加 `(&F)`。
- 跟随系统深色模式，实时切换（现在已经做到）。
- Retina：SVG 图标；图表的 devicePixelRatio 要正确。
- 风格继续用 Fusion + QSS 保证各平台一致，但字号和控件高度用 macOS 的 token（§8.4、§8.5）。

### 13.2 Windows

- 字体是 Segoe UI + 微软雅黑 UI，基准字号 14 px（9 pt）。
- 用“在资源管理器中显示”；菜单可以保留 `(&F)` 助记符。

### 13.3 Linux

- 字体是 Noto Sans + Noto Sans CJK SC；按 CONTRIBUTING 安装 XCB 等系统库。

### 13.4 必须核对的窗口尺寸

960×640（最小）、1280×800、1440×900、1920×1080，每个尺寸在 1× 和 2× 缩放下各看一次。

### 13.5 无障碍（目标 WCAG 2.2 AA）

- 正文对比度 ≥ 4.5:1，界面元素 ≥ 3:1，用脚本校验 token。
- 颜色永远不是唯一的信息通道（§8.3：图标、文字、颜色三者同时出现）。
- 自绘组件和图表都设可访问名称和描述。
- 三个主要任务（DAW 测量、接口测量、对比）都能只用键盘完成。
- 焦点可见。
- 跟随系统字号设置（不写死过小的字号）。
- 在 macOS 上用旁白（VoiceOver）做一次冒烟测试（手动，Phase 7）。

### 13.6 性能预算（Phase 0 先测出现状的基线，再定最终数字）

| 指标 | 目标 |
| --- | --- |
| 打包版冷启动到窗口出现 | ≤ 2.5 s（Apple Silicon） |
| 切换视图 | ≤ 100 ms |
| 打开一次测量 | ≤ 500 ms |
| 3 条叠加曲线的缩放和平移 | ≥ 50 fps |
| 20 次测量的项目 | 后台加载，第一条在 1 s 内出现 |
| 显示缓存 | 沿用 #58 的内存预算 |

## §14 GUI 技术架构

### 14.1 目标目录

```

    overview_model.py      # 结论视图的显示模型（由 AnalysisResult、findings、health 生成）

    components/ （§9.1 的组件，一个组件一个模块）
    charts/     panel.py  plotkit.py（来自 #58）  frequency.py  time.py  decay.py
                noise.py  reflections.py  spectral.py  placement_diagram.py  project_average.py
    views/      welcome.py  overview.py  frequency.py  time.py  decay.py  noise.py

    dev/        gallery.py  experimental_room/（D5：冻结的房间 3D 和扫描）
```

### 14.2 分层规则

- `views/`、`components/`、`charts/` **不导入 `core/`**，只接收 `presentation/` 产出的显示模型，以及 `display/` 产出的曲线数据。
- `presentation/` 是纯 Python，能在没有 Qt 的环境里做单元测试；CLI 的 `render.py` 也逐步改用它，并且 golden 输出不变。
- 只有 `ui/design/` 可以写颜色和尺寸字面量。
- `ui/` 不能被任何非 ui 模块导入（现有规则）。

### 14.3 状态与信号

- 只有一个状态源：`state/app_state.py`（`QObject`），内部持有 #58 的 `WorkspaceModel` 和现在的 `MeasurementState` 语义。
- 信号包括：`entries_changed`、`current_changed`、`overlay_changed`、`baseline_changed`、`take_started/progress/finished/failed`、`analysis_started/finished/failed`、`unsaved_changed`、`scheme_changed`。
- 视图只订阅信号，**页面之间不互相调用方法**。导航和“离开前确认”都由 `router.py` 处理。
- 保留 generation 机制，用来丢弃迟到的结果（C12）。

### 14.4 线程

- 分析、测量、项目加载都在 `QThread` 里运行；UI 线程上单次阻塞不超过 50 ms。
- 关窗口时等待线程结束；测量中关窗口先问是否保存。

### 14.5 测试策略

| 层 | 测什么 | 方式 |
| --- | --- | --- |
| presentation | 格式、用词、和 CLI 一致 | 纯单元测试 + CLI golden |
| 组件 | 每种状态都能构造；有可访问名称；能聚焦 | 离屏 pytest |
| 视图和流程 | 现有的行为测试（迁移过来）+ 新流程 | 离屏 pytest，用 fake 后端 |
| 中文门 | 所有视图、组件、对话框 | 沿用 `test_gui_zh.py` 的做法，并扩展 |
| 样式 lint | `ui/` 中除 `design/` 以外没有 `setStyleSheet(`、没有 `#xxxxxx`、没有写死的 px | 静态扫描测试 |
| 无障碍 | 遍历所有可交互控件，检查 `accessibleName` 非空 | 离屏测试 |
| 视觉 | 组件画廊和页面截图（不做像素比对的门，只做人工评审；以后再考虑感知比对） | 脚本 |
| 性能 | §13.6 的冒烟基准 | `scripts/benchmark.py` 扩展 |

### 14.6 迁移规则

- 测试里引用了很多窗口属性（附录 E）。重构时**要么在同一个 PR 里更新测试并写明原因，要么提供兼容属性**；不能删掉行为断言。
- 每个阶段结束时，README 截图脚本、`SCREENSHOT_PLAN.md`、用户指南里的按钮名称要同步更新。
- #58 的 `docs/design/GUI_2_ARCHITECTURE.md` 改写成 `docs/design/GUI_ARCHITECTURE.md`，内容以本准则为准；`ARCHITECTURE_V1.md` §5.8 加一句指向它。

## §17 执行者工作规则（人和 AI 会话）

1. **开工前**：先读本准则的 §0、§3、§5，以及要改的那一页的规格（§7）和相关章节。从 GitHub 拉最新的 `gui/redesign`；**不要用本机 `~/Documents/RoomScope` 这个旧副本**。
2. **一次只做一件事**：一个阶段里的一个任务，对应一个分支、一个 PR。PR 描述引用章节号。
3. **不顺手改其他东西**：不改 DSP、文件格式、CLI 行为。发现 core 的问题就开 issue，或者单独提 PR。
4. **不擅自加东西**：不新增依赖、图标、字体、色表，除非按 C7 做了审计。
5. **不自行发明新模式**：遇到准则没覆盖到或者有冲突的地方，先停下，在 PR 里写“准则变更提案”（问题、方案、影响），由维护者决定。
6. **不为了让测试通过而删测试**：改测试必须写明原因。
7. **本地验证**（来自 MAINTAINING §4）：
   ```bash
   python3.12 -m venv .venv && source .venv/bin/activate
   pip install -e ".[dev,gui]" build
   ruff check . && ruff format --check .
   mypy
   python scripts/check_doc_links.py && python scripts/check_cli_docs.py && python scripts/check_src_safety.py
   QT_QPA_PLATFORM=offscreen pytest --cov=reverbscope.core --cov=reverbscope.models --cov-fail-under=85
   ```
8. **截图**：用脚本离屏渲染（附录 D）。不得把合成结果说成真实测量；离屏截图不等于真机验收。
9. **Git**：每到一个稳定的阶段，先 commit 再 push；不强推；不删远端分支；不发布 Release，不打 tag；不改许可证；GUI 工作不进 `release/0.5.0`。
10. **如实汇报**：STATUS 和 PR 只写实际运行过的检查；没跑的就写“未运行”。
11. **多代理协作**：同一时间、同一组件或页面只能有一个会话在改；开工前在 PR 或 issue 里认领；不在别人的分支上直接推。
12. **语言**：给维护者的说明用中文；代码注释和提交信息沿用仓库现在的英文风格。

## §18 风险与对策

| 风险 | 对策 |
| --- | --- |
| 重写的范围失控 | 阶段门、评审表、D5 冻结；每个阶段有明确的退出标准 |
| 测试大量改动，行为回退 | C12 不变量；兼容属性；行为测试只迁移不删除 |
| 改了词条影响 CLI | pgettext 上下文；CLI golden；术语改动必须经维护者确认 |
| pyqtgraph 和 PySide6 版本不兼容 | 固定 pyqtgraph 0.14.0 和 PySide6 < 6.12；升级单独提 PR 并跑全部测试 |
| 桌面包变大 | Phase 7 评估移除 matplotlib（终端版本来就不含） |
| 离屏截图和真机不一致 | Phase 7 真机验收；所有截图都标明是离屏 |
| 多个代理冲突 | D13 只有一个集成分支；认领机制 |
| 维护者没时间看 | 每个阶段评审只看画廊、截图和评审表分数 |
| 范围扩张（3D 房间、AI 助手等） | 不在本准则范围内；要做必须先写 ADR |
| 新外壳暴露旧的缺陷 | 缺陷单独修，并且带回归测试 |

## 附录 D：离屏截图脚本（基线与评审用）

先在仓库根目录 `pip install -e ".[gui]"`，再运行 `reverbscope demo` 生成合成数据，然后用 `reverbscope project init --out <demo> --name "合成演示房间"` 和 `reverbscope project add <demo> <demo>/position-a --position A`（B 同理）建一个项目。

`REVERBSCOPE_HOME` 要指到一个临时目录，免得污染真实的最近列表。运行方式：`QT_QPA_PLATFORM=offscreen python -I shoot.py zh_CN light`（语言可选 `zh_CN`、`en`；主题可选 `light`、`dark`）。

```python
"""Grab every page of the ReverbScope GUI offscreen (main 0.5.0b3 layout)."""
import os, sys
from pathlib import Path
os.environ.setdefault("QT_QPA_PLATFORM", "offscreen")
here = Path(__file__).resolve().parent
lang = sys.argv[1] if len(sys.argv) > 1 else "zh_CN"
scheme = sys.argv[2] if len(sys.argv) > 2 else "light"
os.environ["REVERBSCOPE_HOME"] = str(here / "home")
os.environ["REVERBSCOPE_COLOR_SCHEME"] = scheme
out = here / "shots" / f"{lang}-{scheme}"; out.mkdir(parents=True, exist_ok=True)
demo = here / "demo" / "reverbscope-demo"
from PySide6.QtWidgets import QApplication, QScrollArea
from reverbscope.i18n import activate
app = QApplication(sys.argv); activate(lang)
from reverbscope.ui.app import install_qt_translations
from reverbscope.ui.main_window import MainWindow
from reverbscope.ui.theme import apply_application_chrome
install_qt_translations(app); apply_application_chrome(app)
w = MainWindow(); w.resize(1280, 820); w.show()
def settle():
    for _ in range(5): app.processEvents()
def grab(name, widget=None):
    settle(); (widget or w).grab().save(str(out / f"{name}.png"))
def grab_full(name, page):
    settle(); area = page.findChild(QScrollArea)
    if area is None: return
    body = area.widget(); body.resize(area.viewport().width(), body.sizeHint().height())
    settle(); body.grab().save(str(out / f"{name}-full.png"))
w.home.restore_walkthrough(); grab("01-home"); grab_full("01-home", w.home)
w.show_mode("universal_daw"); grab("02-daw"); grab_full("02-daw", w.daw)
w.show_mode("standalone"); grab("03-standalone"); grab_full("03-standalone", w.standalone)
w.show_mode("demo"); grab("04-demo")
w.open_session_path(demo / "position-a")
for i in range(w.results.tabs.count()):
    w.results.tabs.setCurrentIndex(i); grab(f"05-results-{i}")
w.results.tabs.setCurrentIndex(0); grab_full("05-results-0", w.results.overview)
w.show_compare(); w.compare.set_paths(demo / "position-a", demo / "position-b")
w.compare.same_gain.setChecked(True); w.compare.run_compare()
grab("06-compare"); grab_full("06-compare", w.compare)
w.show_project(demo); grab("07-project"); grab_full("07-project", w.project)
w.resize(960, 640); w.show_home(); grab("10-home-min")
w.open_session_path(demo / "position-a"); grab("11-results-min")
```

新外壳上线后，这个脚本要随着属性名一起更新，并最终被 `scripts/render_gallery.py` 和 README 资产脚本取代。
